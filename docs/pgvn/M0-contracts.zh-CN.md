# M0 接口与实现约束

本文件固定后续 M1–M5 的实现边界。M0 只交付可运行的构建骨架、HTTP.sys 与服务生命周期验证，不提供 SVN 仓库协议。声明位于 `src/pgvn/core/pgvn.h`，操作接口从 M1 开始实现；M0 的能力诊断固定返回 false，就绪探针固定返回 503。

## 公共核心

公共核心为静态库，链接进三个入口与配套授权模块，无 RPC 进程。接口私有且跟随固定 SVN 1.14.5 ABI，不作为第三方稳定插件 ABI 发布。返回值使用 `svn_error_t *`，输出对象由调用者 APR pool 持有。仓库对象的 pool 销毁顺序为关闭写流、释放 FS/连接、释放配置快照。一个 pool 不跨并发线程操作。

| 接口 | 契约 |
| --- | --- |
| context_create | 复制受保护的连接配置；缺省连接超时 3 秒、SQL 超时 5 秒；失败消息不回显 DSN 或 SQL 参数 |
| catalog_resolve | 接收已经按协议解码一次的 UTF-8 URL 路径，拒绝反斜线、NUL、`.`、`..`、重复分隔符和非规范形式；按完整路径段最长前缀匹配，返回 ID、UUID、配置代数与库内路径 |
| repo_create | 显式区分内部存储 ID 和 SVN UUID；存储、r0、配置与路由在同一数据库事务创建；并发重名最多一个成功 |
| fs_bind / repos_open | 按 ID 打开已存在的数据库记录，不接受文件系统路径；逻辑身份 `pgvn:<uuid>` 仅供诊断，禁止作为文件操作参数 |
| policy_acquire | generation=0 表示原子获取最新已发布配置与授权；非零必须精确匹配；快照不可变 |
| policy_revalidate | 写操作发布前检查启用状态、配置代数和权限；元数据无法确认时拒绝继续写入 |
| hook_dispatch | 明确事件、仓库 ID、用户、txn/rev；pre 同步拒绝，post 失败报告已提交事实，不回滚 revision |
| status_snapshot | 仅复制有界后台快照，不在 HTTP 请求线程连接数据库或扫描历史；返回时间、实例身份与新鲜度 |

路由与仓库路径使用精确大小写、C 排序规则，沿用 SVN 接受的 UTF-8 形式；不悄悄折叠大小写或混同 NFC/NFD。适配器负责 URL 编码边界，解码后的斜线与原始 `%2f` 必须在协议层作出明确且经过对照的处理。每次请求只使用一个配置快照，通知用于加速，不能代替代数复核。

连接首轮不引入事务池。FS 实例持有自己的有界连接租约，打开写流期间会话 advisory lock 与连接绑定，不得归还通用池。控制与监控连接独立；遥测失败不改变业务事务结果。SQL 错误日志只保留 SQLSTATE、操作名及关联 ID，完整数据库错误不能进入监控 API。

## 认证与 hooks

svn 协议第一种密码认证为上游 CRAM-MD5，匿名访问须显式配置且默认禁止写入；没有合适的凭据提供者时启动检查拒绝开启密码认证。CRAM-MD5 是兼容性选择，远端连接须由受信隧道保护，原协议不提供传输加密。

凭据提供者接口按身份域和用户名取得短生命周期秘密，由服务端提供给上游内存配置对象；禁止将 PostgreSQL SCRAM/MD5 登录摘要当作 SVN 密码。跨节点账号版本存于控制 schema；可解密凭据必须使用部署密钥加密，密钥由独立受保护的全局凭据配置提供，不能写入数据库或仓库记录。服务节点共享经授权分发的密钥版本，轮换采用 key_id 和账号 generation。具体加密实现与凭据 CRUD 在 M3 完成并验收，M0 骨架没有认证能力。

HTTP 身份由 Apache 身份提供者建立，mod_authz_pgvn 使用同一数据库 authz 快照；身份提供者信任边界由部署配置固定。认证用户与 PostgreSQL 业务角色独立。

hooks 定义随配置代数原子发布。处理器首轮支持内置策略和显式配置的外部程序；外部程序位于全局部署目录，禁止动态拼接 shell 命令。传入 JSON 事件及环境变量，超时必须终止自己创建的进程树。默认不运行旧的每库脚本。历史查询使用 pgvnadmin look，pre 与 post 事件均保留上游用户可见语义。提交和 DAV 跨请求恢复测试必须覆盖 post 失败与应答丢失。

## 监控契约

M4 页面使用中文，源文件在 `web/pgvn-monitor`，构建时嵌入产品；M0 的英文简易页仅用于 HTTP 构建验证。无外部资源、Node.js 或 CDN 运行依赖。

| 默认资源 | 上限或语义 |
| --- | --- |
| 监听 | 仅显式 `http://127.0.0.1:PORT/`，1024–65535；M0 拒绝通配与远端地址 |
| HTTP | 2 工作线程，队列 64，单请求头缓冲 32 KiB；拒绝写方法、请求体与未知路径 |
| 超时 | 已路由连接的头部/空闲 5 秒、请求队列 5 秒、实体 5 秒、排空 2 秒、发送速率至少 1024 B/s |
| 数据库采样 | 独立连接，每 5 秒，连接 3 秒、SQL 5 秒；最后成功样本超过 15 秒为 stale，没有样本为 unknown |
| 页面 | 摘要每 5 秒刷新，同一请求不重叠；隐藏标签降频；默认 50 条，最大 200 条 |
| 趋势与事件 | 本地 15 分钟趋势、200 条近期事件，遥测保留 24 小时；白名单指标与时间窗 |
| 只读认证 | Authorization: Bearer，随机 256 bit 令牌只保存摘要；不写 URL、浏览器持久存储、日志或遥测 |

HTTP.sys 在识别首请求的 URL 前使用全局 HeaderWait/IdleConnection，应用的 5 秒值不能覆盖此阶段。M0 已据此设置持续连接测试：先完成 GET，再发送不完整后续头，测量真实超时；另用 16 个不完整首请求证明工作线程仍可响应且服务可停止。运行时不修改整机 HTTP 设置。部署公网访问时由可信反向代理施加连接与首请求超时。依据：[微软 HTTP_TIMEOUT_LIMIT_INFO](https://learn.microsoft.com/en-us/windows/win32/api/http/ns-http-http_timeout_limit_info)。

`/health/live` 不访问数据库，只证明本进程 HTTP/主循环存活；`/health/ready` 使用有时效的采样，schema/配置或写主不可确认时为 503。健康探针不返回业务详情。所有 `/api/monitor/v1/*` 与 `/metrics` 在 M4 实施同源只读认证；未知 endpoint 在 M0 直接返回 404。

状态 JSON 使用 `sampled_at`、`age_seconds`、`freshness=fresh|stale|unknown`、`source`、`node_id`、`instance_id`，缺失数值为 null，不伪造为零。集合响应含 `items`、`limit`、`next_cursor`，错误含固定 `code` 和关联 `request_id`，不透出原始 SQL 错误。先后端定量账本再对比页面。

请求以完成的 SVN 命令或 HTTP 请求计数，标明入口；新 revision 与回执确认分别计数；锁指 SVN 锁而非数据库锁。counter 按启动 instance_id 分开，重启后的归零不转成负速率。标签只含有界组件、操作与结果分类，避免用户名、路径、txn_id、错误全文及任意仓库名成为 Prometheus 标签。Apache 工作进程独立发心跳，pgvnserve 不代计其请求。

固定性能样本：种子 20261015，小 XML、1 MiB/16 MiB 二进制、历史、复制、混合提交；并发 1/8/32；预热 60 秒、稳态 300 秒，各 3 次。M6 在同一 Release 构建按关闭/开启/关闭监控测量吞吐、p95、CPU、内存与 SQL。目标预算为吞吐损耗≤5%、p95 增幅≤10%、额外内存≤64 MiB，这些数值尚未验证。

## Schema 迁移与退出码

迁移顺序必须是显式清单：先 `sql/001_initial.sql` 至 `004_hotcopy.sql`，再 `sql/pgvn/001_catalog.sql` 等 PgVN 迁移。M0 的 schema 设计见同目录 `schema-design.zh-CN.md`；M1 开始实施，M0 不执行虚构的迁移文件。版本表同时记录 migration_id、SHA-256、安装时间；对已安装版本摘要不符应拒绝继续。

进程退出码：0 成功，1 未分类失败，2 用法/结构配置，3 数据库不可达，4 schema 不兼容，5 未授权，6 不存在，7 冲突。协议层继续返回原 SVN 错误含义，HTTP API 返回对应 HTTP 状态。M0 只涉及 0/1/2；其余在对应能力实施时测试。
